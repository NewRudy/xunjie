# 数据合同（data-contracts）

> 三类数据：外部真实数据源、真值标签体系、仿真器规则（负荷/发电/异常注入）。
> 原则：**仿真的可以编，但必须标 SIMULATED；政策与电价必须是真的，且可点查文号。**

## 1. 真值标签（四色，UI 必须可见）

| 标签 | 含义 | UI 呈现 |
|---|---|---|
| `MEASURED` | 真实测量值（真实设备接入时） | 绿色徽标 |
| `MODELED` | 公开模型/算法计算值（PVGIS、Open-Meteo、引擎计算） | 蓝色徽标 |
| `SIMULATED` | 仿真器编造值（负荷曲线、实发、设备状态） | 黄色徽标 |
| `POLICY` | 政府公开文件中的数字（电价、时段、规则） | 灰色徽标 + 可点文号 |

另：fixture 根节点 `fictional: true`，园区场景整体必须在 UI 常驻可见"虚构园区"水印/标注。

## 2. 外部真实数据源

### 2.1 Open-Meteo（逐时气象，免费无需 key）
- 预报：`https://api.open-meteo.com/v1/forecast?latitude=26.65&longitude=106.63&hourly=shortwave_radiation,temperature_2m&timezone=Asia%2FShanghai`
- 历史：`https://archive-api.open-meteo.com/v1/archive?latitude=26.65&longitude=106.63&hourly=shortwave_radiation,temperature_2m&timezone=Asia%2FShanghai&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`
- 已验证可用（2026-08-25 贵阳全天累计 4.30 kWh/m²）。
- 坐标取 fixture anchor（26.4085, 106.5225 贵安新区）时以其为准。
- 缓存策略：SQLite 表 `weather_cache(lat, lon, date, hour, ghi, temp, fetched_at)`；历史数据永久缓存，预报缓存 6 小时。
- 返回数据标 `MODELED`。

### 2.2 PVGIS 锚点
- 贵阳年等效发电：**955 kWh/kWp/年**（PVGIS 实测 E_y=955.45）。
- 用途：应发电量模型的年度标定常数。交叉验证源：Global Solar Atlas。
- 标 `MODELED`。

### 2.3 贵州政策包 `gz-policy`（POLICY，按月版本化）

**宏观政策背景（叙事用，不进计算）：**
- 136 号文：新能源上网电价全面市场化，存量/增量机制电价衔接。
- 《分布式光伏发电开发建设管理办法》：一般工商业"全部自发自用或余电上网"，大型工商业原则上全自用 → 防逆流是刚需，是储能/策略的存在理由。
- 各省机制电价竞价公开（例：山东 0.261、江苏 0.36 元/kWh）。

### 2.4 场景地理数据（P1 用，均公开）
- 底图：天地图（需申请免费 key）或 OSM 离线瓦片（Geofabrik 导出；实时 Overpass 会限流，禁止在线依赖）。
- 屋顶参考：CBRA 数据集（Zenodo 7861676，全国 2.5m）。
- 地形：公开 DEM（SRTM/Copernicus）。
- **红线：不使用"实景三维贵阳贵安"等受控数据。**

## 3. 负荷仿真器规则（SIMULATED，种子确定）

仿真器输入：fixture 的 `loadProfile` + loadType + 日历；输出 15 分钟级曲线。
种子规则：`seed = hash(nodeId + date)`，同日同节点结果完全一致。

各 loadType 的逐时基线系数（0~1，乘以该节点峰值 kW；各分表仿真峰值在 fixture `subMeters[].peakKw` 声明；实现可细化，偏差须可解释）：

- `production_2shift`（两班制生产）：00-07 ≈0.15（基载）；08-12 ≈0.85；12-13 ≈0.5（午休）；13-18 ≈0.9；18-20 ≈0.7；20-24 ≈0.6；其余 0.2。日历系数：周末 ×0.5、法定节假日 ×0.3（两班制周末减产——使 fixture"最大需量约 1500kW"与"年用电约 520 万 kWh"两口径同时逼近）。
- `office`：00-07 ≈0.05；08-12 ≈0.7；12-14 ≈0.3；14-18 ≈0.75；18-20 ≈0.2；其余 ≈0.05。周末与法定节假日 ×0.15。
- `dormitory`：早峰 06-08 ≈0.6；白天 ≈0.15；晚峰 18-23 ≈0.8；夜间 ≈0.25。
- `canteen`（预留，当前 fixture 无楼栋使用）：三餐峰 07-08/11-13/17-19 ≈0.9；其余 ≈0.1。
- `distribution`（配电房小动力，即 park-fixture §3 对 B06 的定义）：日间 08-18 ≈0.4；18-20 ≈0.35；20-22 ≈0.3；其余 ≈0.25。
- `ev_charging`（充电桩，**可调负荷**；作用于 EV-01…04 节点，不是楼栋 loadType）：9-17 时窗口内随机到车（按 fixture EV 车队：工作日 4 辆、周末 2 辆、节假日 1 辆），单车 60kW；策略卡可将其窗口平移到谷段——平移前后曲线都要可查，作为策略收益的证据。

宿舍/食堂/配电房为住人值班负荷，日历不敏感（日历系数恒 1）。

日历：工作日/周末/法定节假日（2026 年国务院安排硬编码进 fixture 或引擎常量）。

## 4. 发电与异常注入规则（SIMULATED）

- 应发（MODELED）：`expectedKwh(h) = capacityKwp × (ghi(h)/1000) × tempDerate(h) × systemLoss × pvgisCalibration`，systemLoss 默认 0.82，pvgisCalibration 使年累计收敛到 955 kWh/kWp。
- 实发 = 应发 × (1 ± 2% 噪声)，种子确定。
- 异常注入：fixture `demoAnomaly` 定义 STR-B2-07 在 ghi>200 W/m² 时段电流 -18%（疑似旁路二极管击穿/热斑），其所属逆变器 INV-B-02 与楼栋 B02 汇总连带可见。
- 恢复：巡检任务 close 后异常立即撤销，之后曲线回到 ±2% 区间（验收矩阵的闭环检查依赖此条）。
- 追加异常类型必须先进本合同（类型、注入规则、证据要求），再进 fixture。

## 5. 数据诚实性的验收锚点

- 政策文号在 UI 可点击，跳转官方发布页或政策包内原文摘录。
- 任何页面出现"元/kWh、元、kWh、kW"数字时，其来源接口必须能在 network 里找到，且带 truth 标签。
- LLM 输出中的数字必须与引擎 JSON 逐字一致（字符串包含检查）。
