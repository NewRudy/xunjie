# 验收矩阵（acceptance-matrix）

> 每个阶段的"完成"定义。任何一行不过，该阶段不算完。
> 通用前缀：所有检查在本地 `pnpm dev`（或等价命令）启动的页面上人工执行，引擎接口用 curl 验证。

## P0 · 合同落盘（本阶段）

| # | 检查项 | 通过标准 |
|---|---|---|
| P0-1 | 合同四件齐 | contracts/ 下 README、semantic-tree、park-fixture、engine-io、data-contracts、acceptance-matrix 均存在且互相引用一致 |
| P0-2 | fixture 可解析 | `JSON.parse` 通过；所有 nodeId 符合语义树规则；demoAnomaly 指向存在的节点 |
| P0-3 | 政策包数字 | data-contracts.md 中政策表每项数字可追溯到文号 |

| # | 检查项 | 通过标准 |

| P1-6 | 数据来源诚实 | 底图/地形来源在关于页列明；无受控数据 |

## P4 · 运维闭环（小人巡检）

| # | 检查项 | 通过标准 |
|---|---|---|
| P4-1 | 异常可见 | 注入 demoAnomaly 后：集控中心告警 + 3D 场景 STR-B2-07 所在位置标红 + 损失电量估算（元/天） |
| P4-2 | 一键演示 | 一个按钮跑通：异常出现 → 创建任务 → 小人对讲机式派单 → 小人沿道路到 B02 楼前 → 切屋面视角 → 提交证据（照片/热成像/读数）→ 闭环 |

## 诚实性一票否决项（任何阶段）

- 页面出现无 truth 标签的数字 → 不通过。
- LLM 产出的数字与引擎不一致 → 不通过。
- 虚构园区未标注 → 不通过。
- 政策数字与文号对不上 → 不通过。
- 用"AI 预测"替代确定性计算 → 不通过。
